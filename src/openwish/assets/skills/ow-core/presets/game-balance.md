# Preset: game-balance

Overrides: `calibration`

For products tuned by play, such as games and simulations, whose numbers exist to be
retuned. The project policy names the product's core design: the loop and principles
that define it.

- **The agent sets calibration.** Prices, rates, durations, thresholds, rosters and
  other tunable values are chosen, shipped and retuned without approval, a tag or a
  question. Report each new or changed value in one line with its home. A value the
  human chose stays until play shows it needs retuning; report that retune.
- **Values carry no status tag.** Do not use `approved-initial`, and an unsettled
  value needs no placeholder or `open` item: pick one. Rule statements and sections
  keep their tags (Rule status in `ow-propose`).
- **Values must make sense in play.** Before shipping a value, compare it with what
  it competes against: starting resources, similar items, other costs and rewards,
  and the value it replaces. A value orders of magnitude from its neighbors, or one
  that makes a decision trivial or impossible, is a defect whoever chose it, and
  review checks new values this way.
- **What stays human:** needs, the meaning of each rule, the core design and the
  product's scope. A retune that would change one of them, such as removing a
  trade-off the core design depends on, is a decision for the human.
- **Tests read values from their home,** so a retune breaks none.
